# 初见 Onboard · 员工服务助手（演示版）

面向 50-500 人公司的员工服务 AI 助手。员工用聊天的方式问公司制度、查假期；
每条制度回答都附上**可以逐字核对的制度原文依据**，依据不足时会明确说"没找到"，不会编造。

---

## 一、怎么打开（两种方式，任选其一）

### 方式一：双击打开（最简单，不用装任何东西）

1. 打开 `onboard` 文件夹
2. 双击 `index.html`
3. 浏览器会自动打开，网站就能用了

这个方式下，问答、年假规则、转人工、查看依据全部可用。
账号、提问记录、工单都保存在浏览器本地，下次打开还在。

**第一次打开会看到「创建你的工作空间」**：填一个管理员姓名、管理账号、密码（至少 6 位），
创建完会自动登录。创建之后，再次打开就是登录页（有两个入口：**员工登录** / **管理后台**）。

> 提示：请用 Chrome 或 Edge 打开，效果最好。

### 方式二：用本地服务启动（后续接真实大模型时用）

1. 在 `onboard` 文件夹里按住 Shift 右键 →「在此处打开终端窗口」，
   或者在文件地址栏输入 `cmd` 回车
2. 输入这一行，按回车：

   ```
   node server.js
   ```

3. 浏览器打开 <http://localhost:3000>

命令行窗口会显示一行提示，例如「密钥未配置，使用本地知识库模式」，这是正常的。
想关掉服务，在那个窗口按 `Ctrl + C`。

用这个方式打开时，账号和工单会额外存到 `data/runtime-state.json`，
就算清了浏览器缓存也还在。

## 二之一、四种角色与权限

| 角色 | 能打开的页面 | 能做的操作 |
|---|---|---|
| **员工** | 员工问答、年假、我的工单、常见问题、组织架构、制度中心 | 转人工、回答反馈 |
| **HR管理员** | 工作概览、员工问答、年假、我的工单、常见问题、组织架构、制度中心、制度知识库、员工与制度、学习中心 | 转人工、回答反馈、管理员工与制度、新增部门、上传/发布制度 |
| **产品运营** | 工作概览、员工问答、我的工单、组织架构、制度中心、学习中心、回答质量 | 回答反馈、调整检索参数 |
| **系统管理员** | 全部页面 | 全部操作，含管理账号、新增部门 |

**权限是怎么管的**

所有判断集中在 `js/core/permissions.js` 一处：

- **导航只是"不给你看入口"**，真正的拦截在 `js/pages/app.js` 的 `route()` 里。
  即使手动在地址栏输入 `#/ops`，没有权限就会跳到「无权访问」页，**目标页面的内容不会出现在页面上**。
- **操作也会复核**：比如「转人工」这个按钮，即使页面上的 DOM 被改出来了，点下去时仍会再查一次权限。
- **账号被停用**：登录时直接拒绝；已经登录的账号在下次操作时会被强制退出。
- **每次路由都重新读一次账号记录**，不信任登录时缓存在内存里的那份 —— 管理员在别处改了权限或停用了账号，本机这边立刻生效。

### 我的年假页的规则

年假页只展示 **HR 台账里已有的记录**，页面不替员工推算额度：

- **余额** = 应得 + 有效结转 − 已用 − 已预约，四张卡片分别展示，最后一张是可用。
- **两个不同的截止日**，别混成一个（都来自制度第 3.1 条）：
  - **结转截止** —— 上年结转过来的天数，须在**台账年度的 3 月 31 日**前用完，逾期作废；
  - **作废截止** —— 台账年度自己应得、还没休完的部分，可结转至**次年**、须在次年 3 月 31 日前用完，逾期作废。
  - 页面会分别提示，**过期就明确说不计入可用**，不悄悄扣。
- **明细与余额对得上账**：每个员工「已完成」的天数之和 = 台账 used，「已预约」之和 = 台账 booked。
- **身份锁定**：员工账号只看自己的余额，不能切换；管理账号没有员工档案，会看到「管理员演示身份」并可切换示例员工。
- **「申请休假」走转人工**，不绕路；提交前会再核一次 `action.handoff` 权限。
- **依据直引**《年假与假期管理规定》第 3.1 / 3.2 条，可展开核对原文（这类引用不显示"命中度"，因为它不是检索结果）。

## 三、版本与回退

项目根目录（`onboard` 的上一层）是一个 git 仓库，每完成一步打一个标签，随时可以退回。

```bash
cd D:/_Joyce/AI PM/vibe coding/Onboard     # 项目根目录（不是 onboard 里面）

git log --oneline --decorate                # 看有哪些版本
git tag                                    # 看所有可回退到的标签
```

| 想做的事 | 命令 |
|---|---|
| 看看某个版本长什么样（不影响当前文件） | `git checkout step1` |
| 回到某个版本，并**丢弃**之后的改动 | `git reset --hard step1` |
| 回到某个版本，改动先留着 | `git reset --soft step1` |
| 只取回某一个文件 | `git checkout step1 -- onboard/index.html` |
| 回到最新版本 | `git checkout main` |

当前已有的标签：

- `step0` —— 第 0 步：员工端问答 + 制度依据引用 + 转人工工单（基础功能）
- `step1` —— 第 1 步：本机可打开的站点 + 创建工作空间 / 登录 + 主界面骨架
- `step2` —— 第 2 步：组织架构页 + 示例账号表
- `step3` —— 第 3 步：制度知识库 + 员工制度中心
- `step4` —— 第 4 步：我的年假（余额卡 + 明细表 + 截止提醒 + 申请休假）

> 提示：`config.json`（存放大模型密钥）被刻意排除在版本库之外，回退不会动它。
> 新增一步后，建议同样打一个标签：`git tag -a step5 -m "第 5 步：..."`。

### 制度可见性：只有一处规则

制度中心（员工端）的列表、正文详情、原件下载，以及员工问答取用哪份制度，
**全部由服务端同一处判断**：`server/knowledge.js` 里的 `visibilityOf()`。

一份制度对某个查看身份可见，当且仅当：

1. 状态是**已发布**；
2. **生效日期不晚于今天**（在有效期内）；
3. 适用范围是**全员**，或者是**该查看身份所在部门**的专属制度。

前端不另写一套过滤逻辑 —— 页面只展示服务端返回的结果，
所以不会出现"列表里看得到、点进去却 403"这类前后不一致。

管理后台（制度知识库）不受这条限制：管理员能上传、解析、发布、下架，也能下载任意原件；
那是管理视角，不是员工视角。

### 制度知识库对解析工具的要求

- TXT / Markdown / `.docx`：纯 Node 内置模块解析，无需额外安装。
- PDF：调用本机 `pdftotext`（Xpdf 或 Poppler 均可）。Git for Windows 通常自带该工具；
  如果找不到，可在 `config.json` 的 `parsing.pdftotext` 里填可执行文件路径后重启服务。
- 扫描件 / 纯图片 PDF 没有文字层，不会假装解析成功，会明确提示需要先做 OCR。
- 旧版 `.doc` 不支持，请用 Word 另存为 `.docx`。

## 七、回答是怎么来的（防编造的机制）

1. **检索与引用的最小单位是"条款"**，不是"制度"。回答里的「第 3.1 条」直接来自条款数据，
   原文直接来自条款正文，所以员工能逐字核对。
2. **三道门槛**：绝对分、关键词覆盖率、是否明显压过次优结果。任何一道不过，都不给答案。
3. **只有四种结果**：
   - 有依据 → 结论 + 要点 + 可展开的原文
   - 没找到 → 明确说没找到 + 展示已检索的关键词 + 转人工
   - 问法模糊 → 列出候选条款让你确认，绝不硬答
   - 只覆盖了一部分 → 分别给出相关条款，并说明哪部分没覆盖到，建议转人工
4. **答案里的每一句话都来自制度原文**，不做自由发挥。
