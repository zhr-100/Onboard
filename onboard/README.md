# 初见 Onboard · 员工服务助手（演示版）

面向 50-500 人公司的员工服务 AI 助手。员工用聊天的方式问公司制度、查假期；
每条制度回答都附上**可以逐字核对的制度原文依据**，依据不足时会明确说"没找到"，不会编造。

---

## 一、怎么打开（两种方式，任选其一）

### 方式一：双击打开（最简单，不用装任何东西）

1. 打开 `onboard` 文件夹
2. 双击 `index.html`
3. 浏览器会自动打开，网站就能用了

这个方式下，问答、年假规则、转人工、查看依据全部可用。
账号、提问记录、工单都保存在浏览器本地，下次打开还在。

**第一次打开会看到「创建你的工作空间」**：填一个管理员姓名、账号、密码（至少 6 位），
创建完会自动登录。创建之后，再次打开就是登录页。

> 提示：请用 Chrome 或 Edge 打开，效果最好。

### 方式二：用本地服务启动（后续接真实大模型时用）

1. 在 `onboard` 文件夹里按住 Shift 右键 →「在此处打开终端窗口」，
   或者在文件地址栏输入 `cmd` 回车
2. 输入这一行，按回车：

   ```
   node server.js
   ```

3. 浏览器打开 <http://localhost:3000>

命令行窗口会显示一行提示，例如「密钥未配置，使用本地知识库模式」，这是正常的。
想关掉服务，在那个窗口按 `Ctrl + C`。

用这个方式打开时，账号和工单会额外存到 `data/runtime-state.json`，
就算清了浏览器缓存也还在。

## 三、版本与回退

项目根目录（`onboard` 的上一层）是一个 git 仓库，每完成一步打一个标签，随时可以退回。

```bash
cd D:/_Joyce/AI PM/vibe coding/Onboard     # 项目根目录（不是 onboard 里面）

git log --oneline --decorate                # 看有哪些版本
git tag                                    # 看所有可回退到的标签
```

| 想做的事 | 命令 |
|---|---|
| 看看某个版本长什么样（不影响当前文件） | `git checkout step1` |
| 回到某个版本，并**丢弃**之后的改动 | `git reset --hard step1` |
| 回到某个版本，改动先留着 | `git reset --soft step1` |
| 只取回某一个文件 | `git checkout step1 -- onboard/index.html` |
| 回到最新版本 | `git checkout main` |

当前已有的标签：

- `step0` —— 第 0 步：员工端问答 + 制度依据引用 + 转人工工单（基础功能）
- `step1` —— 第 1 步：本机可打开的站点 + 创建工作空间 / 登录 + 主界面骨架

> 提示：`config.json`（存放大模型密钥）被刻意排除在版本库之外，回退不会动它。
> 新增一步后，建议同样打一个标签：`git tag -a step2 -m "第 2 步：..."`。

## 四、关于数据

**页面里的所有内容都是虚构的示例数据**，包括员工姓名、制度条款、假期天数、工单记录。
它们不代表任何真实企业的政策，只用于演示这个产品是怎么设计的。

- 制度数据的来源：`data/policies.js`（只读基线，永不修改）
- 员工、假期、工单数据：`data/employees.js`、`data/tickets.js`
- 检索准确率回归测试题：`data/testcases.js`
- 你在网页上做的改动（提问记录、创建的工单）保存在浏览器本地，
  不会写回 `data/` 目录，示例数据随时保持可复现

## 五、关于密钥

**所有机密信息（尤其是大模型 API 密钥）都只放在 `config.json` 一个文件里**，
不会出现在网页文字、示例数据或浏览器网络请求里。

- `config.example.json` —— 不含密钥的模板
- `config.json` —— 你自己的配置（已加入 `.gitignore`，不会被提交）
- 目前 `llm.apiKey` 是空的，说明还没接真实大模型；
  等需要接的时候，填上密钥并把 `llm.enabled` 改成 `true` 即可

## 七、回答是怎么来的（防编造的机制）

1. **检索与引用的最小单位是"条款"**，不是"制度"。回答里的「第 3.1 条」直接来自条款数据，
   原文直接来自条款正文，所以员工能逐字核对。
2. **三道门槛**：绝对分、关键词覆盖率、是否明显压过次优结果。任何一道不过，都不给答案。
3. **只有四种结果**：
   - 有依据 → 结论 + 要点 + 可展开的原文
   - 没找到 → 明确说没找到 + 展示已检索的关键词 + 转人工
   - 问法模糊 → 列出候选条款让你确认，绝不硬答
   - 只覆盖了一部分 → 分别给出相关条款，并说明哪部分没覆盖到，建议转人工
4. **答案里的每一句话都来自制度原文**，不做自由发挥。

### 想验证一下检索准不准？

```bash
node tools/regression.js        # 跑 32 道回归测试题
node tools/regression.js --verbose   # 打印每道题的详情
```

测试题在 `data/testcases.js`，包含 20 道"应该有依据"、10 道"应该答不出来"、
1 道"问法模糊"、1 道"只覆盖一部分"。
